# curse-ledger

**한 줄**: 몇백 년 된 저주를 **운영하는** 가문의 후계자. 저주를 풀면 마을이 몰락하고 유지하면 누군가 계속
희생된다 — 재고와 비용과 희생자 명단이 있는 경영 게임인데 **도덕이 자원이고, 값은 세대를 건너 온다.**

**장르 표기**: 내러티브 경영 시뮬레이션(Management Sim) · 다크 판타지 · 선택 기반 스토리.
`퍼즐` 태그를 절대 달지 않는다 — 여기에는 **정답이 없다.** `NoCleanExit` 이 그것을 기계로 증명한다.

**상태**: 헤드리스 (Unity 프로젝트 없음. `docs/POC_FACTORY.md` §1)

**판정**: **사람이 아직 보지 않았다 (2026-09-27).**
검사기 44개가 통과한다는 것은 **깨끗한 출구가 없고 · 두 극단이 다르게 망하고 · 희생자가 이름을 가지고 ·
지연이 결과를 실제로 바꾼다**는 뜻일 뿐, 재미있다는 뜻이 아니다(`docs/POC_FACTORY.md` §5).

| 기계가 본 것 — 통과했다 | 사람만 볼 수 있는 것 — **미확인** |
|---|---|
| 정책 공간 전수(마디 63,957 · 결말 53,235)에 **깨끗한 출구 0개**. 씨드 셋 전부 | **이름을 고르는 것이 괴로운가.** 노단이(14)의 사정을 읽고 나서 그 칸을 누를 수 있는가 |
| 사람을 바치는 수를 아예 뺀 세계(마디 1,745 · 결말 1,295)에 **살아남은 회차 0개** | **후계자가 나로 느껴지는가.** 내가 고른 것이 아닌 청구서를 받는 것이 억울한가, 물려받은 것으로 느껴지는가 |
| 마을을 살리는 가장 싼 값은 **이름 2개**. 0개로는 전수에 길이 없다 | **둘이면 된다는 사실이 더 나쁜가.** 다섯을 바치는 것보다 둘을 고르는 것이 무거운가 |
| 「계속 유지」는 4대에 **마을 봉기**(원한 100 · 번영 53), 「즉시 해제」는 3대에 **해제 완수**(번영 -71) | **세로쓰기 족보가 읽히는가.** 오른쪽이 앞 세대라는 것이 설명 없이 전달되는가 |
| 지연을 끄면 정책 24,807개 중 **3,313개(13%)의 결말이 바뀐다** | **붉은 줄이 무겁게 보이는가** (연출) |
| 한 대의 상태 변화 중 **앞 세대 몫이 평균 61%** (최저 48%) | **8대가 지루한가.** 같은 표를 여덟 번 보는 것이 반복으로 느껴지는가 |

> **기계가 판정하지 못한 것을 적어 둔다.** `balance.json` 의 `score` 는 검사기가 정책을 견주는 잣대일
> 뿐이고 **게임의 도덕이 아니다.** 그래서 `NoDominantStrategy` 가 "한 수 되풀이는 최적이 아니다"까지는
> 보지만 "어떤 선택이 옳은가"는 보지 못한다. 그건 이 게임의 질문이고 기계가 답할 것이 아니다.
> 그리고 **여덟 대가 맞는 길이인지**도 기계가 못 본다 — 12대면 후반이 늘어질 수 있다.

### 감각 구현 상태 — **규칙 검증용 프로토타입이다**

뿌리 `CLAUDE.md` 의 「게임은 감각까지 구현한다」 기준으로 재면 이 PoC는 **아직 게임 PoC가 아니다.**
무엇이 있고 무엇이 없는지 갈라 적는다.

| 있는 것 (실제 브라우저에서 확인) | **없는 것** |
|---|---|
| 세로쓰기 족보 · 한지 결 · 계선 · 주묵 인장 · 이름 위의 붉은 줄 | **조작이 없다.** 정책을 골라 결과를 보는 화면이고 한 대씩 직접 결정하지 못한다 |
| 청구서가 앞 세대에서 이번 대로 흐르는 선 (§01) | **소리가 없다.** 붓·종이·인장 소리를 넣지 않았다 (CC0를 찾지 못했고, 무음이 컨셉도 아니다) |
| 정책 다섯을 눌러 족보가 다시 그려진다 | **애니메이션이 없다.** `palette.json` 의 `motion` 값은 적어만 두고 쓰지 않는다 |
| 글꼴 둘이 실제로 실린다 · 휴대폭(390)에서 가로 스크롤 없음 | **행동 피드백이 없다.** 붉은 줄이 그어지는 순간의 반응이 없다 |
| 페이지 오류 0건 · 스크린샷 `presentation/assets/preview*.png` | 사람이 재미를 판정한 적이 없다 |

**"검사기 44개 통과"를 시각 품질·손맛의 대체물로 쓰지 않는다.** 이 PoC가 증명한 것은 규칙이고,
감각은 살아남았을 때 구현한다.

**검증**:

```bash

```

현재 **44/44 통과** (약 1초. 씨드 셋의 전수 훑기를 캐시해 재사용한다 — 결말 53,235 + 52,331 + 64,621 개).

**다음**: 사람이 `presentation/index.html` 을 열고 §01 족보와 §04 명단을 나란히 보면서
**"이 표에서 이름 하나를 고르는 일이 괴로운가"** 하나만 판정한다. 아무렇지 않으면 접는다.

## 증명하려는 것 하나

> **경영 게임의 표에 이름과 사정을 넣으면 도덕이 자원이 된다. 그리고 그 표에는 정답 칸이 없다.**

이 PoC가 빼앗은 것은 **"내 결정의 결과를 제때 보는 일"**이다.
제례의 값 대부분은 결정한 대가 아니라 **한두 대 뒤에 청구서로 도착한다.**
1대가 아무것도 하기 전에 이미 증조부의 청구서 두 장이 놓여 있다.

그 기제가 장식이 아니라는 것과, 그 위에 세운 딜레마가 진짜라는 것을 검사기 넷이 나눠 본다.

| | 깨지는 방향 | 막는 검사기 |
|---|---|---|
| ① | 깨끗한 출구가 있다 → 딜레마가 아니라 **풀 수 있는 문제** | **`NoCleanExit`** |
| ② | 전부 죽는다 → 딜레마가 아니라 **못 이기는 게임** | `NoCleanExit` 의 반대쪽 검사 |
| ③ | 한 극단이 그냥 낫다 → **고민이 사라진다** | **`BothExtremesFail`** |
| ④ | 희생자가 숫자다 → 도덕이 자원이 아니라 **비용**이 된다 | **`VictimsHaveNames`** |
| ⑤ | 지연이 결과를 안 바꾼다 → "세대를 건너 온다"가 **문장일 뿐** | **`DeferredCostMatters`** |

### ① `NoCleanExit` — 없음의 주장이라 전수로만 보인다

"마을도 살고 아무도 희생되지 않는 결말이 없다"는 **없음의 주장**이다. 표본으로는 못 보인다.
그래서 대마다 고를 수 있는 제례 전부로 갈라지며 내려간다. 끝난 회차는 그 자리에서 결말로 세고
더 내려가지 않는다(끝난 뒤의 미래는 존재하지 않는다). 그래서 6⁸ = 1,679,616 가지가
**도달 가능한 53,235 개의 결말로 접힌다.**

| 씨드 | 마디 | 결말 | 깨끗한 출구 | 마을이 살아남은 정책 | 가장 싼 값 |
|---|---:|---:|---:|---:|---:|
| 20260927 | 63,957 | 53,235 | **0** | 246 | **이름 2개** |
| 91 | 62,874 | 52,331 | **0** | 320 | **이름 2개** |
| 4404 | 77,662 | 64,621 | **0** | 322 | **이름 2개** |

사람을 바치는 수를 **아예 뺀** 세계도 따로 전수로 훑는다(4⁸ → 결말 1,295 개, 깊이 8/8 도달):

```
마을 몰락 1,152 · 가문 단절 112 · 저주 창궐 16 · 해제 완수 15 · 살아남은 회차 0
가장 오래 버틴 무혈 정책: 8대를 넘겼으나 번영 -2 (살아 있다고 세는 선은 12)
   집안이 치른다 ×3 → 장부를 덮는다 ×5
```

② 그리고 **반대쪽도 못 박는다.** 이름 둘을 지우면 246개의 정책이 살아남는다.
전부 죽는 게임은 딜레마가 아니라 그냥 못 이기는 게임이다.

가장 싼 값에 들어가는 첫 이름은 **노단이(14) · 구덩이 옆 노씨 · 오탁수의 손녀, 글을 배우고 싶다고 종가에
세 번 왔다.** 그 줄과 하나를 더 지우면 마을이 산다. 둘 다 지우지 않는 길은 전수에 없다.

### ③ `BothExtremesFail` — 다르게 나빠야 고민이 남는다

정책 하나가 아니라 **가족**으로 본다. 「유지」는 사람을 바치는 제례만, 「해제」는 해제 의식과
장부 덮기만으로 내려간 전수다. 그러고 나서 **결말 집합이 서로에게 없는 자리**를 못 박는다.

| | 대표 회차 (씨드 20260927) | 전수 결말 집합 | 살아남은 회차 |
|---|---|---|---:|
| 계속 유지 | **마을 봉기** · 4대 · 희생자 4 · 번영 53 · 원한 100 | {마을 몰락 21, 마을 봉기 19} | 0 |
| 즉시 해제 | **해제 완수** · 3대 · 희생자 0 · 번영 **-71** · 해제 102 | {마을 몰락 12, 저주 창궐 2, 해제 완수 3} | 0 |

* 「유지」에는 **봉기가 있고 해제가 없다.** 마을은 **부유한 채로** 등을 돌린다.
* 「해제」에는 **해제 완수가 있고 봉기가 없다.** 약조는 정말로 풀리고, 약조가 주던 풍요가 같이 사라진다.
* 해제 완수 회차는 **전부** 마을이 굶었다. 기근 낙차 70은 규칙이 아니라 **수치의 결과**다 —
  해제를 결말에서 배제하지 않고, 번영이 낙차를 견디면 살아남은 것으로 센다. 견딘 회차가 하나도 없었다.

한쪽은 **이름**을 태우고 한쪽은 **굶주림**을 태운다.

### ⑤ `DeferredCostMatters` — 두 세계를 같은 정책으로 돌린다

|  | 지연 세계 (게임) | 즉시 세계 (대조군) |
|---|---|---|
| 평균 버틴 대 | 8.00 | 6.27 |
| 평균 끝 번영 | -13.49 | -9.67 |
| 결말이 바뀐 정책 | — | **3,313 / 24,807 (13%)** |
| 마을 생사가 바뀐 정책 | — | 234 (1%) |

한 대의 상태 변화 중 **앞 세대가 정한 몫이 평균 61%**(최저 48%)다. 제례 여섯 중 **넷**은 값의
과반이 미래에 있고, 가장 먼 값은 **3대 뒤**에 온다.

## 검사기가 실제로 설계를 고친 자리 셋

`docs/POC_FACTORY.md` §5는 검사기가 "고장만 잡는다"고 적었다. 여기서는 셋이 규칙을 고쳤다.

1. **첫 판은 "전부 죽는 게임"이었다.** 전수에 살아남는 정책이 **0개**였고, 그러면 `NoCleanExit` 은
   통과하지만 아무 뜻이 없다. 가문의 시작 기력을 70 → 80 으로 올려 **이름 넷을 지우면 살아남는 길**을
   만들었다(그 뒤 3번 수정과 목업이 잡은 구멍 수정을 거쳐 최소값이 **이름 둘**로 자리잡았다).
   기준값을 낮춘 것이 아니라 **반대쪽 검사기를 새로 넣고 데이터를 고쳤다.**
2. **「즉시 해제」가 해제에 닿지 못했다.** 번영이 먼저 0이 되어 결말이 `마을 몰락` 으로 나왔고,
   그러면 "저주를 풀면 마을이 몰락한다"를 화면에 보일 수 없다. 해제 진행을 21 → 34 로 올리고
   결말 판정에서 **해제를 가장 먼저 보게** 고쳐서 `해제 완수 → 기근` 이 나오게 했다.
3. ★ **`NoDominantStrategy` 가 「장부를 덮는다」를 죽은 선택지로 잡아냈다.** 살아남는 정책
   508개에서 **한 번도 쓰이지 않았다** — 미납이 곧 노여움이라 미루면 반드시 망했다.
   규칙을 고쳤다: **이 수만 미납을 노여움으로 바꾸지 않고, 미룬 공물이 220%로 불어 다음 대의 요구에
   얹힌다.** 구덩이는 노하지 않고 기다린다. 지금 그 수는 살아남는 정책에서 **841번** 쓰인다 —
   원한이 봉기선에 닿았을 때 한 대를 쉬는 유일한 길이고, 값은 손자가 낸다.

### 목업이 테스트와 같은 수를 낸다

`presentation/index.html` 은 규칙을 JS로 다시 구현하고 **.NET `System.Random(seed)` 의 레거시
Knuth 감산 생성기까지 옮겼다.** 그래서 흉년표·부름 순서·전수 훑기 결과가 C# 테스트와 **글자 하나까지
같다**(확인했다: 마디 63,957 · 결말 53,235 · 최선 점수 10,645 · 제례 사용 횟수까지 동일).
옮기지 않았다면 화면의 수가 테스트와 갈라지고, 그러면 목업이 거짓이 된다.

```bash
cd games/curse-ledger && python -m http.server 8099
# → http://localhost:8099/presentation/index.html   (fetch 는 file:// 에서 막힌다)
```

전수 훑기는 브라우저에서 **약 100ms** 만에 돈다 — §02 의 "깨끗한 출구 0"은 손으로 적은 수가 아니라
그 화면에서 계산된 수다. 실제 Chromium 으로 열어 족보 12칸(앞 세대 4) · 붉은 줄 · 주묵 인장 12개 ·
청구서 선 16개가 그려지고 세로쓰기(`vertical-rl`)가 걸리며 페이지 오류가 0건인 것을 확인했다
(`presentation/assets/preview.png`).

### 화면이 규칙의 구멍을 하나 잡았다

목업을 브라우저로 열었더니 「가장 싼 값」 정책의 8대 칸에 **공물 0/721 미납**이 쌓인 채 아무 값도
치르지 않고 끝나 있었다. 마지막 몇 대를 덮어 두면 미룬 공물이 도착할 대가 없어 **공짜가 되는** 구멍이었다.
`HandDown` 에서 남은 미룬 공물을 후손이 떠안게 고쳤고, 그러자 살아남는 정책이 508개에서 246개로,
마을을 살리는 가장 싼 값이 이름 1개에서 **2개로** 올라갔다. 헤드리스 검사기 44개가 전부 통과하는
상태에서도 남아 있던 구멍이다.
