# locked-phone

**한 줄**: 죽은 사람의 휴대폰. 잠금은 풀 수 없다.
**잠금 화면 하나가 게임 전체다** — 알림 · 부재중 전화 · 배터리 잔량 · 사진 메타데이터,
그리고 알림은 쌓이다 밀려 사라진다. 그것만으로 마지막 하루를 다시 세운다.

**장르 표기**: 1인칭 추리 어드벤처 · 조사(Investigation) · 내러티브.
`퍼즐` 태그를 달지 않는다 — 논리 문제가 아니라 **무엇을 언제 볼지 고르는 일**이어야 하고,
`NoDominantStrategy` 와 `PushoutForcesWakes` 가 그것이 진짜인지 기계로 본다.

**상태**: 헤드리스 (Unity 프로젝트 없음. `docs/POC_FACTORY.md` §1)

**판정**: **사람이 아직 보지 않았다 (2026-09-27).**
검사기 41개가 통과한다는 것은 **잠금 화면만으로 풀리고 · 한 장으로는 안 풀리고 · 밀려남이 실제로
시간을 만들고 · 반복이 최적이 아니다**라는 뜻일 뿐, 재미있다는 뜻이 아니다(`docs/POC_FACTORY.md` §5).

| 기계가 본 것 — 통과했다 | 사람만 볼 수 있는 것 — **미확인** |
|---|---|
| 잠금 화면만으로 정답 **3/3**. 잠금을 풀어도 답이 달라지지 않는다 | **잠금 화면 하나만 보는 것이 답답한가, 숨 막히는가.** 이 PoC의 생사다 |
| 잠긴 쪽만으로도 **3/3** — 대조군이 비어서 이긴 것이 아니다 | 밀려 사라진 알림을 봤을 때 아까운가, **억울한가** |
| 미리보기를 끄면 **0/3** — 일하는 것은 표면에 뜬 내용이다 | **죽은 사람에게 계속 오는 문자가 견딜 만한가.** 여기가 가장 위험한 자리다 |
| 알림 한 장으로도 두 장으로도 **0/3**. 필요한 14장은 하나만 빠져도 무너진다 | 8px EXIF 를 들여다보는 일이 몰입인가 불편인가 |
| 밀려남 끄면 깨우기 **2번**, 켜면 **4번**. 한 번만 깨우면 **0/3** | 배터리가 줄어드는 것이 긴장인가 스트레스인가 |
| 고정 박자 189가지 중 전부 세운 것 **0가지** | 세 물음에 답하고 나서 **더 알고 싶어지는가** |

> **기계가 판정하지 못한 것 둘을 적어 둔다.**
> ① 이 PoC는 소재가 위험하다. "죽은 사람 휴대폰에 계속 문자가 온다"는 장치가
> 긴장으로 읽힐지 불쾌로 읽힐지 검사기는 전혀 보지 못한다. 불쾌하면 접는다.
> ② 사진 백업 알림이 **촬영 장소**를 잠금 화면에 띄우는 것은 실제 기기 동작을 한 칸 늘린 허구다.
> 카드 승인·문자 미리보기·부재중 전화·저전력 알림은 실제 그대로지만, 이 한 가지는 아니다.
> 이것이 거짓말처럼 느껴지는지도 사람만 볼 수 있다.


현재 **41/41 통과** (약 3초).

**"이 여섯 장 사이에서 언제 화면을 깨울지 고르는 일이 재미있는가"** 하나만 판정한다.
사무적이거나 불쾌하면 접는다.

## 증명하려는 것 하나

> **정보를 주는 창구를 하나로 줄이고 그마저 사라지게 하면, 남는 것이 게임인가 불편인가.**

보통 추리 게임은 증거를 **가져다 놓는다**. 여기서는 증거가 **저절로 도착하고 저절로 사라진다.**
플레이어가 할 수 있는 일은 **언제 볼지 고르는 것 하나뿐**이다.
그 빼앗음이 진짜로 게임을 만들었는지는 말로는 못 정한다 — 그래서 핵 검사기가 **세 가지를 껐다 켠다.**

## 규칙

| | |
|---|---|
| **할 수 있는 일** | 화면을 깨우는 것 하나 |
| **비용** | 깨울 때마다 잔량 26‰. 가만히 둬도 10분마다 4‰ |
| **주운 순간** | 20:25 · 잔량 196‰ (19%) |
| **칸** | 8장. 넘치면 오래된 것부터 밀려 나가고, **잠금을 풀 수 없으니 영영 못 본다** |
| **잔량 감소율** | 45분 이상 벌려 **두 번** 읽어야 알 수 있다 |

**배터리가 증거인 이유.** 저전력 알림이 20:12에 "배터리 20%"라고 말했고, 주운 20:25의 잔량은 196‰다.
20%(200‰)에서 대기 감소분 한 칸(4‰)만큼만 줄어 있다 —
**그 사이에 화면이 한 번도 켜지지 않았다**는 뜻이다. 그 사실이 사망 시각을 앞으로 당긴다.
`DataValidator` 의 `저전력_알림과_잔량이_서로_맞는다` 가 이 계산을 데이터에 대고 다시 확인한다.

**소식이 퍼지면 화면이 통째로 쓸린다.** 22:45와 23:35에 문자가 여덟 통씩 몰려 들어온다.
칸이 여덟 장뿐이라 그 순간 **앞의 모든 것이 사라진다** — `22:42부터 10분 사이에 8장이 쓸려 나간다.`
이 게임에서 시간이 가장 잔인해지는 자리다.

## 핵 검사기 하나 — `LockscreenSuffices`

**정답이 잠금 화면에 뜬 것만으로 도출되는가.** 이 주장은 잠긴 쪽이 비어 있으면 **공짜로 참이 된다.**
그래서 잠긴 쪽(사진첩 · 통화 기록 · 메시지 전문 · 건강 앱 · 메모 · 은행 앱)에 **답을 통째로** 넣어 두고
네 세계를 견준다.

| 세계 | 세운 정답 | 쥔 사실 | 필요한 깨우기 | 한 번만 깨우면 |
|---|---|---|---|---|
| 잠금 풀림 (답이 애초에 있다는 확인) | 3/3 | 13/13 | 2 | 2/3 |
| **잠긴 쪽만** (알림을 하나도 못 본다) | **3/3** | 13/13 | — | — |
| **잠금 화면** (이 게임) | **3/3** | 13/13 | **4** | **0/3** |
| **미리보기 끔** (알림이 왔다는 것만) | **0/3** | **1/13** | — | — |

마지막 줄이 이 검사기의 **이빨**이다. 그것이 없으면 "잠금 화면으로 충분하다"가
"알림이 있다는 사실만으로 충분하다"는 훨씬 약한 주장과 구별되지 않는다.

정답 셋과 드는 알림:

| 물음 | 정답 | 드는 알림 |
|---|---|---|
| 18:00~19:00 사이 어디에 있었는가 | 형의 가게 (한섭목공) | 4장 |
| 그날 마지막으로 **직접 만난** 사람은 | 형 한지섭 | 6장 |
| 계단에서 떨어진 것은 몇 시인가 | 20시대 | 7장 + 잔량 두 번 |

곁들여 — **필요한 알림 14장 전부 예산 안에서 잡을 수 있다** (가장 좁은 창 21분, 집주인 22:31 문자).
닿을 수 없는 증거가 있으면 그건 어려운 게 아니라 고장이다.

## 핵 검사기 둘 — `NoSingleNotificationGivesItAway`

**알림 하나만으로 정답이 나오지 않는가.** 하나로 끝나면 퍼즐이 아니다.

| 본 것 | 결과 |
|---|---|
| 알림 39장 각각 **단독으로** (잔량까지 공짜로 얹어 주고) | 정답 **0개** |
| 필요한 14장의 **짝 91가지** 전부 | 정답 **0개** |
| 필요한 14장을 **하나씩 빼 본다** | 전부 정답이 무너진다 (군더더기 0) |
| 필요하지 않다고 적은 25장을 하나씩 빼 본다 | 전부 그대로 선다 (목록이 맞다) |
| 잔량을 한 번만 읽으면 | 2/3 — 「몇 시인가」가 무너진다 |

세 번째 줄이 중요하다. 같은 사실로 가는 길이 두 개면 하나를 빼도 안 무너지고,
그러면 **"밀려 사라졌다"가 아프지 않다** — 이 게임의 시계가 멈춘다.

## 핵 검사기 셋 — `PushoutForcesWakes`

앞의 둘은 논리를 본다. 그런데 **밀려남이 없으면 끝까지 기다렸다 한 번 깨우면 전부 보인다** —
그러면 이 게임에 시간이 없다. 이 검사기가 그 자리를 막는다.

| | 밀려남 끔 | **밀려남 켬** |
|---|---|---|
| 전부 세우는 데 필요한 깨우기 | 2번 (잔량을 두 번 읽어야 해서) | **4번** |
| 한 번만 깨워 세우는 정답 | 2/3 | **0/3** |
| 한 번에 화면에 보이는 필요 알림 | 14/14 | **7/14** |

곁들여: **필요한 알림 14장 중 8장이 주운 뒤에 도착한다** (가장 늦은 것 23:55).
밀려남만 있으면 "무조건 일찍 봐라"가 답이 된다 — 늦게 오는 증거가 있어야 결정이 생긴다.

### 공통 검사기 셋

| 검사기 | 본 것 | 결과 |
|---|---|---|
| `SeedDeterminism` | 같은 씨드 두 번 → 같은 화면·같은 일정·같은 결과 | 네 세계 전부 일치 |
| | 씨드 8개가 서로 다른 잡음을 만드는가 | 8가지 전부 다르다 |
| | 씨드 8개에서 부호가 뒤집히는가 | 안 뒤집힌다 (전부 3/3, 밀려남이 깨우기를 2번 이상 늘린다) |
| `DataValidator` | 참조 무결성 · 사진만 EXIF · 정답 선택지 하나 · 지울 방법 있는 선택지 | 통과 |
| | **저전력 알림의 20% 와 주운 잔량 196‰ 가 대기 감소분으로 맞는가** | 맞는다 (한 칸) |
| | **한 번 밀려난 알림이 되살아나는가** | 39장 전부 안 되살아난다 |
| `NoDominantStrategy` | 쉬지 않고 깨운다 (1·2·5·10분마다) | **전부 0/3** — 배터리가 먼저 죽는다 |
| | 끝까지 아꼈다 몰아 깨운다 (2~5번) | **전부 0/3** — 이른 증거가 이미 사라졌다 |
| | 고정 박자 189가지 (10~140분 · 시작 0~30분) | **0가지** 성공. 60분 이하 박자의 최고 성적 2/3 |
| | 예산 여유 | 마지막 증거까지 최대 5번 · 실제로 필요한 것 4번 → **여유 1번** |
| | 같은 순간 연타 | 더 보이는 알림 0장 (배터리만 26‰ 씩) |

## 연출 — 잠금 화면 그 자체

검정 OLED(`#000000`, 타협하지 않는다) · 굵기 100의 큰 얇은 시계 · 가는 배터리 링 ·
반투명 유리 알림 카드 · **8px EXIF**. 값은 전부 `presentation/palette.json` 에 있다.

**UI 장식이 아니라 UI가 곧 게임 화면이다.** 목업 §01은 하루 중 여섯 시각의 잠금 화면을
나란히 세운다 — 같은 전화기, 시각만 다르다. 카드가 쌓이고, 점선으로 바뀌고(12분 안에 밀려난다),
사라진다. §05는 같은 일을 지도로 그린다: 가로줄 하나가 알림 하나, 칠해진 구간이 화면에 있었던 시간,
붉은 띠가 **소식이 퍼져 화면이 통째로 쓸린** 자리다.

목업(`presentation/index.html`)은 `data/` 의 JSON 다섯 장을 읽어 **밀려남·배터리·증거 딱지·사실·정답을
브라우저에서 다시 계산한다.** `System.Random` 까지 그대로 옮겨서 씨드가 만든 잡음 알림이
검사기와 같은 시각에 들어온다. 그림과 검사기가 어긋나면 그것 자체가 고장이다.

> 화면에 붙은 호박색 테두리와 `!` 표시는 **목업이 붙인 주석**이다. 실제 잠금 화면에는 그런 표시가 없다 —
> 무엇이 증거인지 고르는 것이 플레이어의 일이기 때문이다.

## 함께 만든 짝 — `games/scent-layers`

두 PoC는 기제를 공유한다: **한 사건의 마지막 하루가 흔적으로만 남아 있고, 플레이어는
그 흔적을 시간순으로 복원한다.** 잃어버리는 방식이 다를 뿐이다 —
저쪽은 냄새가 **옅어지며 섞이고**, 여기서는 알림이 **밀려 사라진다.**
둘 다 "그 잃어버림이 실제로 게임을 바꾸는가"를 두 세계 비교로 판정한다.
로직은 공유하지 않는다(`docs/POC_FACTORY.md` §6 — 복사하면 갈라진다. 여기는 애초에 다른 로직이다).
