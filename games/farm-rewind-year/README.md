# farm-rewind-year

**한 줄**: 연말에 할당량을 못 채우면 봄으로 되감을 수 있지만, 되감은 횟수만큼 땅의 토질이
깎여 다시는 돌아오지 않는 게임. 되감기는 편의가 아니라 **값을 치르는 규칙**이다.

**장르 표기**: 농장 경영 · 시간 루프 · 자원 관리 (Farming Sim / Time Loop / Resource Management)
— 스토어에서 "퍼즐"로 분류되면 위험하다(`docs/PLAN_GENRES.md §1` §2). Farming Sim을 앞에 둔다.

**상태**: **헤드리스** (수직 슬라이스. Unity 셸 없음, 사람 플레이 미확인)

**판정**: 2026-09-27 · 사람이 플레이한 결과 **없음.** 기계 판정만 끝났고, **가장 중요한 질문에
기계가 답하지 못했다.**

* 기계가 확인한 것 — 흔적이 실제로 듣는다. 되감기 20회에 봄 토질 합 **924 → 292**(바닥 80),
  포도(최소 토질 58)를 받을 수 있는 칸 **9 → 0**, 완전한 지식으로도 사다리 앞 3분의 1 평균 수입
  5,817이 뒤 3분의 1에서 **3,104**로 내려간다. 할당량 3,900에 대해 **벽은 되감기 2회**에서 처음 나타나고,
  **세 정책 모두 되감아서 첫 해보다 더 남기지 못한다**(배우지 않는 되감기: 4,217 → 982).
  첫 해는 넘길 수 있되 여유가 **317코인**뿐이다.
* **기계가 답하지 못한 것 — 이게 이 PoC의 핵심 미확인 사항이다:**
  **사람의 학습이 흔적을 이기는가.** 여기 쓴 탐욕 정책은 이기지 못한다. 실측으로
  완전한 지식(연말 현금 4,076)이 무지(4,217)보다 **141코인 덜 남겼다**.
  이유는 규칙이 아니라 정책이다 — 사람은 한 해의 윤작을 계획하지만 이 정책은 하루하루
  가장 점수 높은 작물을 심을 뿐이다. `Choose`에 '기다리기'를 넣어 봤다가 뺐다
  (하루 점수 × 남은 일수로 견주면 먼 미래가 과대평가되어 밭을 비워 두고 더 못 벌었다).
  **그래서 "되감을 가치가 있는가"는 사람이 플레이해서 판정해야 한다.**
  → 검사기 `RewindHypothesisTests.지식의_값을_실측해_남긴다`는 이 수치를 **출력만 하고
  부호를 판정하지 않는다.** 기계가 볼 수 없는 것을 보는 척하지 않기 위해서다
  (`docs/POC_FACTORY.md` §5).
* 사람만 판정할 수 있는 나머지 — 되감을 때 "아깝다"가 오는가, 토질이 깎인 봄이
  **다른 봄으로 보이는가**, 같은 해를 다시 사는 것이 학습으로 느껴지는가 반복으로 느껴지는가.

### ContentBudget 실측 (이 PoC의 산출물 중 하나)

```
달력                    한 해 112일. 되감아도 늘지 않는다
실제 플레이 일수        2,352일 (되감기 20회 포함)
사건 간격               7일마다 새 사건 · 사건당 4줄 · 되감기 변주 6줄
한 해를 채우는 사건      16개 = 64줄
되감기 변주             20단계 × 6줄 = 120줄
필요한 고유 사건        36개
필요한 고유 대사        184줄
재사용이 없었다면       1,344줄   ← 같은 플레이 시간을 확장형으로 채울 때
되감기가 아껴 준 양      1,160줄 (86%)
지금 있는 사건          9개 = 36줄
부족분                  사건 27개 · 대사 148줄
사람이 감당한다고 본 선  사건 96개 · 대사 384줄   → 예산 안에 든다
```

**이 훅의 실제 값이 이 표에 있다.** 플레이 시간이 2,352일로 늘어도 **달력은 한 해뿐**이라
새로 쓸 것은 되감기 단계별 변주 120줄뿐이다. 같은 시간을 확장형 파밍으로 채우면 1,344줄이 든다 —
**86%를 아낀다.** 1인 개발에서 이 장르의 1순위 실패 원인이 콘텐츠 양이라면
(`docs/PLAN_GENRES.md §1` §8), 되감기는 그 축을 직접 누르는 훅이다.
(비교: `games/farm-erosion`은 같은 예산 안에서 328줄이다.)

**다음**: 사람이 한 판(첫 해 + 되감기 2~3회)을 플레이해서 **"되감을 때 아까운가, 되감은 봄이
다른 봄으로 보이는가"**를 판정한다. 기계는 여기까지가 한계다.

## 규칙 요약 — 데이터가 정하는 것

| 규칙 | 어디에 있는가 | 값 |
|---|---|---|
| 한 해가 전부다 | `seasons.json` | 28일 × 4계절 = 112일. 달의 주기도 28일이라 계절마다 정확히 한 번 찬다 |
| 연말 할당량 | `economy.json → quotaCoin` | 3,900. 못 채우면 봄으로 되감는다 |
| **흔적 = 토질 저하** | `plots.json → rewind` | 되감기마다 **모든 칸 −4** (바닥 5), 한도 20회 |
| 되감아도 같은 해 | `WeatherCalendar` · `PriceBook` | 한 해 분량만 뽑아 재사용. **기억이 값을 갖는 근거** |
| 되돌아가는 것 | `Simulation.ResetYear` | 날짜 · 현금 · 산 칸 · 심어 둔 것 · 그 해에 깎인 토질 |
| 되돌아가지 않는 것 | `Simulation.Rewind` | 되감기 흔적**만** |
| 확장은 봄에만 | `plots.json → expansion.deadlineDayInYear` | 28일까지. 늦게 산 칸은 한 해 안에 값을 못 뽑고, 되감으면 그냥 사라진다 |
| 계절을 못 견디면 죽는다 | `Simulation.ApplySeasonTransition` | 씨앗값과 그 칸의 시간이 같이 사라진다. **이 마감이 "언제 심는가"를 판단으로 만든다** |
| 폭풍은 진행도를 지운다 | `seasons.json → growthLossPoints` | 폭풍 −130 · 서리 −35 (하루 이상적 성장 = 100점) |

### 왜 흔적으로 토질을 골랐나

세 후보(토질 저하 · 값 상승 · 선택지 감소) 중 **토질**이 통로가 가장 짧다.
토질 하나가 성장 속도(`soilFactor = 50 + soil/2`)와 심을 수 있는 작물(`minSoil`)을
**동시에** 좁힌다. 그래서 흔적이 수치 하나로 남으면서도 화면에서는
"포도를 심을 칸이 없어졌다"로 읽힌다. 작물 7종의 `minSoil`과 총수익이 같은 방향으로 오르도록
데이터를 맞췄고(`DeadCropChecker.작물이_토질_사다리를_이룬다`가 그것을 지킨다),
되감기는 그 사다리를 한 칸씩 내려가게 만든다.

값 상승은 표가 하나 더 필요하고, 선택지 감소는 "왜 사라졌는지"를 따로 설명해야 한다.
둘 다 나중에 더할 수 있지만 PoC 단계에서는 통로 하나로 충분하다.

## 설계 메모 — 조율하면서 배운 것

* **진행도를 백분율로 깎으면 성장에 천장이 생긴다.** 폭풍이 "쌓아 둔 진행도의 35%"를
  지우게 했더니 하루 성장 60점 · 손실 8%에서 750점에 멈춰, **보리·포도가 영원히 익지 않았다**.
  죽은 작물 셋이 여기서 나왔다. 정액(−130점)으로 바꾸자 사다리가 살아났다.
* **"모르는 쪽"의 추정을 100%로 두면 안 된다.** 예지 밖의 날을 성장률 100%로 가정했더니
  무지한 정책이 낙관 편향이라는 **이득**을 얻어 되감기가 손해가 됐다. 계절 평균으로 바꿨다
  ("겨울은 느리다"는 되감지 않아도 아는 사실이다).
* **검사기를 결과에 맞춰 고치는 것과, 틀린 주장을 고치는 것은 다르다.**
  "완전한 지식이 무지보다 더 남긴다"는 한계값을 데이터에 두었다가 **뺐다** — 성립하지 않았고,
  성립하게 만들려면 규칙을 부풀려야 했다. 대신 검사기를 규칙 쪽으로 옮겼다
  (되감기가 이득이 아니다 · 흔적이 단조롭게 쌓인다 · 사다리가 끝난다). 이쪽이 더 강한 주장이고,
  못 본 것은 판정 칸에 적었다. `data/economy.json`의 `_예지값_없음`에 그 경위를 남겨 두었다.
