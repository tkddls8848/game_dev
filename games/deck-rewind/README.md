# deck-rewind

**한 줄**: 적의 다음 수는 보이지 않고, 전투는 회차당 세 번 되감을 수 있다. 되감으면 적이 그것을 기억해 같은 수를 다시 두지 않고 더 세게 때린다.

**장르 표기**: 로그라이크 덱빌더 (Roguelike Deckbuilder · Card Battler · Turn-Based Tactics).
퍼즐 태그는 붙이지 않는다 — 손패가 무작위이고 적의 수가 숨겨져 있어 정해진 해가 없다.
`docs/PLAN_GENRES.md §2` §3의 1순위 후보 "되감기"를 그대로 구현한 것이다.

**상태**: 헤드리스 (수직 슬라이스). Unity 프로젝트 없음 — `docs/POC_FACTORY.md` §1대로 헤드리스로 태어났다.

**판정**:
*기계가 본 것 (2026-09-27)* — 검사기 38개 전부 통과. 고장은 없다.
지배 전략 없음(단일 카드 덱 최고 승률 3%) · 사장 카드 없음(최저 채택률 34%) ·
준최적 승률 64%, 무작위 0% · 씨드 재현 완전 · 되감기가 난수 상태까지 정확히 되돌린다.
**측정으로 알아낸 것 하나**: 처음 정책은 "크게 맞으면 되감는다"였는데 승률 34%로,
되감기를 아예 안 쓰는 57%보다 **나빴다**. 적의 기억이 전투 내내 남으므로 선불 되감기는
남은 전투 전부를 비싸게 만든다. 정책을 "죽었을 때만"으로 바꿔 69%가 됐다
(`RewindRuleTests.성급하게_되감으면_손해다` 가 이걸 못 박았다).
*사람이 봐야 하는 것* — **재미는 미확인이다.** 아직 아무도 손으로 플레이하지 않았다.
특히 이 둘은 기계가 못 본다:
(1) 적의 수를 모르고 맞는 것이 **긴장**인가 **답답함**인가
(2) 되감기가 **결단**처럼 느껴지는가 아니면 **세이브 로드**처럼 느껴지는가.
`docs/PLAN_GENRES.md §2` §3이 "되감기가 있으면 긴장이 사라질 수 있다"고 적은 그 위험이
아직 살아 있다. 검사기가 통과한 것은 **고장이 없다**는 뜻일 뿐이다.

## 규칙 — 되감기의 대가

되감기가 공짜면 규칙이 아니라 편의다. 그래서 되감기에는 **되돌려지지 않는 것이 셋** 있다:

| 되돌아오는 것 | 되돌아오지 않는 것 |
|---|---|
| 체력 · 방어 · 적 체력 | 충전 (회차당 3회) |
| 손패 · 덱 · 버림 · **난수 상태** | **적의 기억** — 되감을 때마다 적 피해 +18~22% (누적) |
| 낸 카드 · 기력 | **적의 패턴 오프셋** — 같은 수를 다시 두지 않는다 |
| 라운드 | **플레이어가 본 것** — 그 수를 다시 만나면 이제 안다 |

이게 규칙의 전부다. 되감기의 값은 **정보**다: 되감기 전에는 적의 의도를 모르고,
되감은 뒤에는 방금 본 의도를 안다. 대가는 그 정보가 부분적으로만 유효하다는 것
(적이 수를 바꿨다)과 남은 전투가 비싸진다는 것이다.

측정값:
* 공격 10이 기억 0/1/2에서 실제로 주는 피해: **10 / 11 / 13** (백분율 정수 + 나머지 누적)
* 여덟 라운드 누적 피해: 되감기 0회 **69** → 2회 **94**
* 되감기를 쓰는 준최적 64% vs 안 쓰는 59% — **쓰는 쪽이 낫지만 차이는 작다.** 그게 의도다

## 구조

```
src/            순수 C#. using UnityEngine 없음
  Rng.cs          씨드 고정 난수. (씨드, 호출 횟수) 두 정수로 스냅샷·복원된다
  Data.cs         JSON 스키마 + 로더
  Battle.cs       전투 상태 기계 + 되감기(스냅샷/복원/기억)
  Agents.cs       무작위 · 준최적(탐욕) · 되감기 정책 셋
  RunEngine.cs    회차 진행 + 몬테카를로
  Localization.cs 한국어 원문 + 영어 덮어쓰기
data/           cards.json(10종) · enemies.json(3종) · runs/run_01.json · balance.json
tests/          NUnit. 검사기 여섯 + 규칙 테스트
presentation/   palette.json · index.html · scene.json(생성물) · assets/
```

`src/`는 **같은 장르의 다른 연출**이 아니라 **다른 규칙**이다 (`games/deck-openhand`는 공개 덱).
`docs/POC_FACTORY.md` §2가 금지하는 것은 연출 변형을 위해 로직을 복사하는 것이고,
규칙이 다르면 로직도 다르다. **이 PoC의 연출 변형을 만들 때는 복사하지 말고
`ProjectReference`로 이 폴더를 가리킬 것.**

## 검사기 — Phase를 닫는 것 (`docs/PLAN_GENRES.md §2` §5)

| 검사기 | 파일 | 재는 것 | 지금 값 |
|---|---|---|---|
| `DataValidator` | `DataValidatorTests.cs` | 참조 무결성 · 스키마 | 통과 |
| `SeedDeterminism` | `SeedDeterminismTests.cs` | 같은 씨드 = 같은 기록. 되감기가 난수까지 되돌리는가 | 통과 |
| `RunSolvability` | `RunSolvabilityTests.cs` | 준최적으로 이길 수 있는가 | 21/30 씨드 |
| `DominanceChecker` | `DominanceCheckerTests.cs` | 단일 카드 덱 승률 ≤ 55% | 최고 3% |
| `DeadCardChecker` | `DeadCardCheckerTests.cs` | 채택률 ≥ 5% · 벌이 되는 보상 없음 | 최저 34% |
| `WinRateBand` | `WinRateBandTests.cs` | 무작위 0~5% · 준최적 40~80% | 0% / 64% |
| (규칙) | `RewindRuleTests.cs` | 되감기의 값과 대가가 둘 다 있는가 | 통과 |
| (원칙 6) | `LocalizationTests.cs` | 표가 없어도 한국어가 나오는가 · 언어가 굳지 않는가 | 통과 |

한계값은 전부 `data/balance.json`에 있다. 테스트에 매직 넘버를 두지 않는다 —
판정선이 숨으면 밸런스를 고칠 때 무엇이 움직였는지 알 수 없다.

> **구간의 목표값 자체는 확인하지 못한 것이다** (`docs/PLAN_GENRES.md §2` §10).
> 기존 성공작의 실제 승률 분포를 모른다. `balance.json`의 구간은 "옳은 값"이 아니라
> **이 PoC가 지금 어디 있는지를 고정하는 값**이다. 카드를 고치면 어디로 움직였는지가 보인다.

## 연출 — 차가운 실험 기록

청사진 · 모눈종이 · 얇은 선 1px · 고정폭 글꼴 하나(JetBrains Mono) · 슬레이트 바탕에 시안 강조 하나.
되돌릴 수 있다는 것이 극적인 것이 아니라 **계측된 것**처럼 읽히게 한다.
색 · 크기 · 필터값은 전부 `presentation/palette.json`에 있고 HTML에는 박혀 있지 않다.

목업 보기 (저장소 뿌리에서):
```bash
python -m http.server 8000 --directory games/deck-rewind
# http://localhost:8000/presentation/
```
`file://`로 열면 브라우저가 `fetch`를 막는다 — 목업이 `data/`의 **실제 JSON**을 읽기 때문이다.
전투 장면(`presentation/scene.json`)도 손으로 쓴 것이 아니라
`tests/SceneExportTests.cs`가 실제 시뮬레이션에서 굽는다. 그래서 데이터를 고치면 목업이 같이 바뀐다.
