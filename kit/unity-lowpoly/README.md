# Playable low-poly Unity PoCs

## Runtime files

`Art.cs` was one 442-line file holding sea, island, props and the map scene, so parallel work on
the presentation always collided. It is split by **zone**; each file is a `partial class LowpolyGame`.
Keep methods in their zone — moving them back makes it one file again.

| File | Zone |
|---|---|
| `LowpolyGame.cs` | controller: game loop, camera transform, input, evidence capture |
| `Staging.cs` | lighting, ambient, quality, `Mat()` — **the material every cube uses** |
| `ArtCore.cs` | shared primitives (`Cube` `Rock` `Beam` `Roof` `Tri` `MeshObject`) used by every zone |
| `ArtSea.cs` | sea surface, shore foam ring, offshore stacks, distant islands, mist |
| `ArtIsland.cs` | island silhouette (`landGrid`/`CoastSegments`), cliffs, plots, retaining walls |
| `ArtProps.cs` | cottage, trees, fences, crops, decor |
| `ArtMapScene.cs` | the other PoC (puzzle-tomorrow-map). Leave alone when working on the farm |
| `Hud.cs` · `Feedback.cs` | interface · motion and audio triggers |
| `Soundscape.cs` | music, wind, synthesised surf, one-shots |

Shaders: `Water` · `Atmosphere` · `Faceted` · `Mist` (four, not three).
**Every shader found at runtime via `Shader.Find` must be registered in `Editor/PocBuild.cs`**
(Always Included Shaders) or it resolves in the editor and throws only in the player.

`ArtIsland.FarmScene()` builds `landGrid` and `CoastSegments` first and calls `SeaSurface()` **last**,
because the foam ring reads the real coastline. Reordering those breaks the shore.

Build entry point: `Editor/PocBuild.cs`.
Run `python kit/tools/build_lowpoly_projects.py` from the repository root to synchronize both projects.
It also **prunes** stale copies — files removed from `kit/` are deleted from the projects, otherwise a
split file leaves its old twin behind and the same partial class is defined twice.
The generated copies under each Unity project should not be edited independently.

Unity: 6000.0.81f1, built-in renderer, legacy input, Windows x64.
Open `games/<slug>/unity`, then `Assets/Scenes/Main.unity` and press Play.
The scene is generated by `PocBuild.Build` during the first build.

Build from PowerShell (replace the slug):

```powershell
$p = Start-Process 'C:/Users/PSI/Unity/Hub/Editor/6000.0.81f1/Editor/Unity.exe' -Wait -PassThru -NoNewWindow `
  -ArgumentList '-batchmode','-quit','-nographics','-projectPath','C:/Users/PSI/orca/game/games/farm-erosion/unity',
                '-executeMethod','PocBuild.Build','-logFile','C:/Users/PSI/orca/game/games/farm-erosion/unity/build.log'
$p.ExitCode
```

**`-Wait -PassThru` is required.** `Unity.exe` is a GUI-subsystem binary: called without it the call
returns immediately, `$LASTEXITCODE` is empty, and the next batchmode run fails with
*another Unity instance is running*. Read the log from the **file**, not stdout.
Do not hide the window when capturing screenshots — hidden-window captures come out black.

Output: `unity/Build/TomorrowMap.exe` or `unity/Build/FarmErosion.exe`.
Distribute the complete Build directory, including `_Data`, MonoBleedingEdge and UnityPlayer.dll.
Run with `--poc-smoke` to exercise gameplay and write real engine screenshots plus `Evidence/smoke.txt` next to the executable, then exit.

Map uses the canonical exported `data/graph.json`. Farm copies the existing pure C# data/simulation, excluding the Newtonsoft filesystem loader; Unity loads the same JSON through JsonUtility.
The manual farm API reuses automatic simulation growth, harvest, loss, weather, water allocation, and upkeep methods. Automatic policy tests remain unchanged. Interactive actions happen before each day's simulation; no automatic planting or defense occurs.

Selected Kenney house, tree and fence models are CC0. The revised scene uses the Kenney fence; original house/tree imports remain available. Gothic A1 is SIL OFL. Copies of licenses and model SHA-256 provenance are included in each project's `Assets/ThirdParty`. The revised dioramas generate buildings, tiled roofs, faceted cliffs, crops, foliage, residents and desk props in code. Water/atmosphere shaders, foam/smoke motion, falling cliff fragments, ambulance arrival and brief interaction tones are implemented. AI mockups are separate reference images, not engine captures.

Scope: one map puzzle with three outcomes; one deterministic 24-plot farm with six crops, seasonal costs and bankruptcy/land-loss endings. No save/load, campaign, controller support or polished character animation. Sound is implemented (music, wind, synthesised surf, action one-shots) — see `Soundscape.cs`. Automated validation does not establish human fun or commercial readiness. See [`compare.html`](https://github.com/tkddls8848/game/blob/main/docs/poc-gallery/lowpoly/compare.html) (다른 저장소) for the reference, previous build, revised build and consecutive erosion frames, and [`rounds/`](https://github.com/tkddls8848/game/blob/main/docs/poc-gallery/lowpoly/rounds/) (다른 저장소) for per-round captures held against the approved mockup. The farm's target is written out as measurable requirements in [`ART_TARGET.md`](https://github.com/tkddls8848/game/blob/main/games/farm-erosion/docs/ART_TARGET.md) (다른 저장소). Texture detail and fluid effects still fall short of the AI reference; this is a visual revision, not a claim of full reference fidelity.

### 시안 차이에 대한 재작업

최초 구현은 시안의 감각을 충족하지 못했다. 기능 검증을 게임 구현 완료로 보고한 판단을 정정한다. [시안·이전 구현·재작업 비교](https://github.com/tkddls8848/game/blob/main/docs/poc-gallery/lowpoly/compare.html) (다른 저장소)에 실제 실행 화면과 침식 연속 캡처를 남겼다.

- 도시: 작업 책상과 도면, 층수·외관이 다른 건물, 기와·창·발코니·보도·가로등·주민·병원·구급차를 구성했다. 도면 미니맵과 민원 HUD로 바꾸고 승인 후 구급차 이동을 추가했다.
- 농장: 절벽 단면·풀·농가·작물 형태를 다시 만들고 수면 셰이더·포말 움직임·굴뚝 연기·낙석을 추가했다. 침식 예보와 하단 행동 HUD를 구성했다.
- 두 실행 파일을 재빌드하고 규칙 흐름 smoke 검증을 다시 통과했다. 실제 캡처를 비교해 카메라 확대와 수면 격자 무늬를 수정했다. OS 화면 캡처는 사용하지 않았다.
- **남은 차이:** 시안 수준의 재질·자연스러운 물보라·안개·인물 움직임은 부족하다. 농장 기준 시안은 16칸이 남은 상황이며 비교 캡처는 22칸으로 플레이 상태도 다르다. 사람의 시각 만족·조작감 판정은 미실시다.

### 검증

- 기존 지도 규칙 테스트 8개 통과.
- 농장 테스트 49개 통과: 기존 46개와 수동 조작 검증 3개.
- 두 Windows 빌드 `POC_BUILD_SUCCEEDED`, 컴파일 오류·CS 경고 없음.
- 실행 파일 `--poc-smoke`: 지도 세 결말, 농장 심기·제방·성장·수확·운영 종료 통과.
- 실제 NVIDIA Direct3D 11 환경에서 한글 UI와 3D 화면을 캡처해 확인했다. 숨긴 창에서의 캡처는 검게 나와, 정상 표시한 게임 창으로 재검증했다.
- 각 `unity/Build/Evidence`에 시작·진행·결과 이미지와 `smoke.txt`를 남겼다.
- 별도 OS 마우스 자동화는 창 포커스 확보에 실패해 검증 결과에서 제외했고 해당 캡처를 삭제했다. 물리 마우스 입력을 통한 전체 흐름과 사람 대상 사용성은 아직 확인하지 않았다.

### 구현 및 범위

지도의 정답·결말은 기존 C#에서 내보낸 graph.json을 따른다. 농장은 기존 Simulation에 수동 행동 API를 추가하고 성장·침식·날씨·수확 계산을 공유한다. 매일의 실행 순서에 따라 침식 한계에 도달한 밭은 다음 날 소실 판정된다. 자동 물 배분은 기존 우선순위 규칙을 따른다.

보유 Kenney CC0 집·나무·울타리를 사용했다. 땅·도로·병원·구급차·작물은 절차적 기본 도형이다. Gothic A1 한글 폰트는 SIL OFL이며 모델 출처·해시와 라이선스는 각 프로젝트 Assets/ThirdParty에 포함했다.

이 단계는 핵심 규칙을 직접 조작하는 PoC다. 저장·불러오기, 사운드, 캠페인, 세밀한 캐릭터·붕괴 애니메이션은 포함하지 않는다. AI 시안의 세부 묘사를 모두 재현한 완성 아트가 아니며 사람 대상 재미 검증은 아직 하지 않았다.

실행 파일을 옮길 때 Build 폴더 전체를 복사해야 한다. 프로젝트의 원본 로직·공통 화면을 수정한 뒤 `python kit/tools/build_lowpoly_projects.py`로 Unity 사본을 동기화한다.
