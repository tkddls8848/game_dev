## 한눈에

1. **엔진과 무관한 핵심은 그대로 둔다.** 순수 C# `src/` + `dotnet test` 0.3초 게이트가 이 저장소의 실제 자산이고, 모든 권고는 이것을 깨지 않는 선택지만 남겼다. 로직을 Lua·GML·C++·Python으로 옮겨야 하는 엔진(Defold·GameMaker·Unreal·Ren'Py)은 **#103 하나를 빼고는 1순위로 두지 않는다.** #103 은 옮길 규칙이 없어서 이 비용이 생기지 않는다.
2. **주 엔진은 Unity로 유지한다. 다만 이제 "Unity 6000.0 + 내장 파이프라인"이 아니라 "Unity 6.3 LTS + URP"로 바꾸는 결정이 필요하다.** 6.0 LTS 지원은 **2026-10-16**에 끝나고, 내장 파이프라인은 6.5부터 폐기 절차에 들어가며 Unity가 신작에 쓰지 말라고 명시했다. URP로 가면 수면·데칼·2D 라이트·후처리 볼륨을 손으로 짜지 않아도 된다(`farm-erosion`이 세 라운드째 수작업 중인 바로 그 부분).
3. **3D 조명·공간형(17)과 디오라마형(12), 그리고 3D 액션 1개 — 합계 30개는 Unity URP 3D.** 이유는 3D 에셋 생태계 · 수면/굴절 셰이더 자산이 URP용이라는 점 · 이미 검증된 Unity 셸 3개 · 2026-09-26에 한 결정(3D면 Unity)이 여전히 유효하다는 점.
4. **2D 위주 69개도 1순위는 Unity URP 2D로 둔다 — 두 번째 엔진을 들이는 비용을 아직 정당화하지 못했기 때문이다.** Godot 4.7 .NET은 2D에서 실측상 더 빠르다(빌드 1.4초 · 프로젝트 락 없음 · 라이선스 없음 · 씬이 텍스트). 이 이점은 진짜지만 kit·갤러리 촬영기·셸 규약을 두 벌로 유지하는 비용과 맞바꿔야 한다. **[검증 방법 §2](#검증-방법)의 하루짜리 대조 실험 한 번으로 결정한다.** 그 전에는 대안 열에만 둔다.
5. **웹(TypeScript + PixiJS/Phaser)은 두 역할만 맡는다.** (a) 지금처럼 슬라이스 단계의 HTML 재생기(규칙 검증용 프로토타입), (b) 공유 링크가 유통 경로인 데일리 챌린지형 2개(#21 · #39)의 1순위. 웹으로 갈 때 로직은 **다시 쓰지 않고** .NET WASM(`[JSExport]`)으로 불러오거나, 작으면 `silent-baton`처럼 대조 하네스를 둔 이식으로 간다.
6. **Unreal은 1개 — #103 아무것도 없는 산책.** 걷기만 하는 실사 산책이라 옮길 규칙이 없고, 실사 풍경과 소리가 상품 전부다. 나머지는 그대로다 — 가장 무거운 렌더(#78 폭풍의 등대지기)도 C# 로직을 C++로 옮기는 비용과 헤드리스 게이트 상실을 정당화하지 못한다. 실사가 곧 상품인 3D 14개(클러스터 D)는 **대안 열에만** Unreal 을 적었고, 옮길지는 #103 의 Unreal PoC 로 실측한 뒤 정한다([검증 §7](#검증-방법)).
7. **포기하는 것(트레이드오프).** Unity를 유지하면 프로젝트 락 · batchmode 라이선스(코드 198) · 분 단위 컴파일을 계속 감수한다. Godot을 2D에 들이면 C# 웹 내보내기가 없고(4.7.2 기준) 엔진이 둘이 된다. 웹을 넓히면 오디오·입력 지연과 3D 조명 품질을 직접 짜야 한다. **어느 쪽도 공짜가 아니며, 지금 가장 싼 결정은 "Unity 버전·파이프라인 갱신"이다.**

### 이 표에서 가장 중요한 두 줄

* **Godot 이식은 이미 한 번 했고 결과가 남아 있다.** "2D면 Godot, 3D면 Unity"가 당시 결론이었고, 결정은 3D 가능성 때문에 Unity였다. 이 문서는 그 결론을 뒤집지 않는다 — **103개 중 30개가 3D를 요구하므로 Unity는 어차피 남는다**(#103 은 Unreal). 열린 질문은 "나머지 2D 69개에 두 번째 엔진을 쓸 것인가"뿐이다.
* **지금 당장 비용이 드는 것은 엔진 교체가 아니라 Unity 판 갱신이다.** 6.0 LTS 지원 종료(2026-10-16)와 batchmode 라이선스 갱신일(2026-10-24, 2026-09-26 문서 기준 · 현재 유효 여부 미확인)이 같은 달에 있다.

### Unreal 은 왜 하나뿐인가

Unreal 을 뺀 근거는 처음부터 둘이었다 — **C# 규칙을 C++ 로 옮기는 비용**과 **`dotnet test` 게이트 상실**.
3D 공수가 커서가 아니었다. 그래서 "AI 가 Unreal 배경 작업을 해 준다"는 사실은 이 두 근거를 건드리지 않는다.

* **#103 만 둘 다 0 이다.** 걷기만 하는 안이라 옮길 규칙이 없다.
* **실사가 상품인 3D 14개**(5 6 15 16 29 30 31 32 33 34 37 38 40 78)는 Unreal 로 가면 더 좋아 보일 **수** 있다.
  그러나 31·32(균열 경로) · 33·34(바뀐 전시물 대조)처럼 헤드리스 ◎ 규칙이 있는 안이 대부분이라 두 비용이 그대로 남는다.
  그래서 1순위는 Unity URP 3D 로 두고 대안 열에만 Unreal 을 적었다.
* **14개를 옮길지는 실측으로 정한다**([검증 §7](#검증-방법)). 옮기게 되더라도 C# 은 버리지 않는다 —
  C# 규칙이 정답 기록(JSON)을 내고 Unreal 쪽 구현이 그 기록과 같은지 견주는 **대조 하네스**(`silent-baton` 방식)로 간다.
* 29·30·38 은 사람이 나온다. AI 가 줄여 주는 것은 **배경**이고 인물·애니메이션 공수는 그대로다 (추정).

## 결정이 필요한 것

사람이 정해야 한다. 에이전트가 기본값으로 밀어붙이지 않는다.

1. **Unity 판 갱신 — 6000.0.81f1 → 6.3 LTS, 내장 → URP.** 뿌리 `CLAUDE.md`가 에디터 경로·버전을 고정하고 있으므로 바꾸려면 그 문서부터 고친다. 6.0 LTS 지원이 **2026-10-16**에 끝난다. 기본 권고: 새 셸은 6.3 + URP로 시작한다.
2. **기존 Unity 셸 3개를 어떻게 할까.** `mystery-blackwood`(가장 크다 · 내장 후처리 `CameraGrade`) · `farm-erosion`(시안 대비 작업 중) · `puzzle-tomorrow-map`. 선택지: (a) 동결 — 6.0·내장에 둔다 (b) 셋 다 옮긴다 (c) farm-erosion만 옮겨 수면 문제를 URP로 다시 푼다. **farm-erosion 비평 라운드 도중에 옮기면 비교 기준이 흔들린다** — 라운드를 닫고 옮길지 정해야 한다.
3. **2D에 두 번째 엔진(Godot .NET)을 허용할까.** 허용하면 kit·셸 규약·촬영기를 두 벌 유지한다. 허용하지 않으면 2D 69개도 Unity 락·라이선스·분 단위 순환을 감수한다. [검증 §2](#검증-방법) 결과로 정하자.
4. **출시 플랫폼.** 기본 가정은 Steam 데스크톱(PLAN_GENRES 전부 Steam 기준). 예외 후보 — 모바일 네이티브(#27), 웹 데일리(#21 · #39, 그리고 #3의 일일 시드). 이 셋을 실제로 웹·모바일로 낼지가 정해지면 표의 1순위가 바뀐다.
5. **웹 빌드의 지위.** 지금 HTML 재생기는 "규칙 검증용 프로토타입"이다. 웹을 **출시물**로도 인정할지(그렇다면 감각 무타협 기준을 웹에도 똑같이 건다), 슬라이스 전용으로 둘지.
6. **대본이 수백 개인 컨셉에 작가 도구를 쓸까.** #17(편지 80) · #23(사연 300) · #42·#67(긴 대본). Ink를 쓰면 데이터 형식이 하나 더 생긴다.
7. **batchmode 라이선스 갱신(2026-10-24, 이전 문서 기준).** 날짜가 여전히 맞는지 (미확인) — 맞다면 1과 같이 처리한다.
8. **Unreal 을 두 번째 엔진으로 들일까.** 지금은 #103 하나다. 들이면 저장소에 C++/Blueprint 프로젝트와 수십 GB 의 엔진이 생기고, 뿌리 `CLAUDE.md` 의 환경 표에 Unreal 경로를 더해야 한다. [검증 §7](#검증-방법) 결과로 14개까지 넓힐지 정한다.

## 검증 방법

전부 하루 안쪽으로 끝나게 잡았다. **엔진을 바꾸는 결정은 실측 없이 하지 않는다** — 2026-09-26에 한 방식 그대로다.

1. **URP 전환 비용 (결정 1·2).** `farm-erosion`을 별도 브랜치에서 6.3 LTS + URP로 연다.
   재는 것: 셰이더 4개 중 그대로 도는 수 · 고친 줄 수 · `error CS`/`warning CS` · 같은 16/24 국면 `compare.png`를 [`ART_TARGET.md`](https://github.com/tkddls8848/game/blob/main/games/farm-erosion/docs/ART_TARGET.md) 항목표로 채점 · 수면을 Shader Graph로 다시 만든 시간.
   합격선(제안): 순수 로직 무수정 + 시안 항목 점수가 현재 이상.
2. **2D 엔진 대조 (결정 3).** 클러스터 A의 구현작 하나(권장: `gods-secretary` #68 — 편지·도장·한글이 많다)에 **같은 날 두 셸**을 붙인다: Unity 6.3 URP 2D와 Godot 4.7.2 .NET.
   재는 것: `src/` 무수정 컴파일 여부 · 셸 줄 수 · 콜드/웜 빌드 시간 · 테스트와 게임 동시 실행 가능 여부(락) · 한글 폰트(손글씨 포함) 렌더 품질과 IME · 촛불 2D 라이트 · 시안 대비 스크린샷 · 에이전트가 씬을 텍스트로 고친 횟수.
   이전 측정(Godot 셸 904줄로 핵심 루프, 빌드 1.4초)을 기준선으로 쓴다. **Godot이 속도에서만 이기고 시안 비교에서 지면 채택하지 않는다.**
3. **웹에서 로직 재사용 (결정 4·5).** `silent-baton`의 `src/`를 `dotnet new wasmbrowser` + `[JSExport]`로 빌드해 `presentation/engine.js`(187줄 손 이식)를 대체한다.
   재는 것: 기존 `tests/browser-parity.js`가 그대로 통과하는가 · 압축 후 번들 크기 · 첫 로드 시간(데스크톱/모바일). 너무 크면 데일리형은 "손 이식 + 대조 하네스"로 간다.
4. **무음 리듬 지연 (#47 · #65).** 같은 기기에서 HTML 판과 Unity 판의 **키 입력 → 화면 변화**를 240fps 휴대폰 촬영으로 30회 잰다. 판정 창 폭과 비교해 엔진 선택이 체감에 영향을 주는지 본다.
5. **마이크 (#24).** Unity 데스크톱에서 `Microphone` + `GetData` 폴링으로 실시간 음량·무음 검출 루프를 만들고 장치 분리/재연결, Windows 권한 거부를 확인한다. 한 시간짜리 프로토타입이면 된다.
6. **Ink 헤드리스 (결정 6).** Ink C# 런타임을 한 게임의 테스트 프로젝트에 넣고 컴파일된 스토리 JSON을 `dotnet test`에서 전 분기 순회할 수 있는지 확인한다. 안 되면 Ink는 기각한다.

## 확인하지 못한 것

* URP(6.3)가 볼류메트릭 광선·포그를 기본 제공하는지. Unity는 2026 전략에서 URP에 HDRP급 기능을 넣는다고만 밝혔다
* Godot 4.7의 C# 모바일 내보내기 현재 상태(4.2 기사 기준 실험적) · C# 웹 내보내기 일정(시연은 2025-05, 4.7 릴리스 페이지엔 언급 없음)
* .NET WASM 번들 크기와 첫 로드 시간 — 이 저장소에서 잰 적 없다
* 저장소의 반사·볼류메트릭 셰이더 자산(`AdamPlaneReflection`, `VolumetricLights`)이 URP에서 도는지
* 바이노럴 공간화에 어떤 플러그인을 쓸지와 라이선스
* Unity batchmode 라이선스 갱신일(2026-10-24)이 지금도 맞는지
* MonoGame·FNA의 정확한 라이선스 조건 — 비권장이라 더 파지 않았다
* AI(에디터 MCP)로 Unreal 배경을 만들 때 실제로 줄어드는 공수 — 영상 한 편 외에 근거가 없다
* UE 5.8 에 실험적 MCP 플러그인이 들어 있다는 보도 — 공식 문서로 확인하지 않았다
